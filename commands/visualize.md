# Visualize

引数 `$ARGUMENTS` で指定した資料やトピックの内容を、専門用語・根拠・件数を保ったまま図と構造で読み解ける HTML に組み替える。

## 目的

平易化(eli5 的な言い換え)は、専門用語が比喩に置き換わる・根拠(原文引用・ファイルパス・行番号・出典URL)が落ちる・列挙項目の件数が落ちる、という問題を起こしやすい。本コマンドは図解と構造化の読みやすさを活かしつつ、用語と根拠を削らずに再構成することを目的とする。

## 原則

- **用語を言い換えない**。製品名・API名・設定キー・識別子・条項番号・エンドポイントは正式名称のまま使う。比喩や日常語への置き換えをしない。
- **根拠を落とさない**。元資料にあるファイルパス・行番号・出典URL・原文引用は残す。
- **件数を落とさない**。列挙項目は省略せず全件載せる。「主なものは」といった間引きをしない。
- **削るのは文章量であって内容ではない**。散文を表・リスト・図に組み替えて読みやすくする。要約して情報量を減らすことではない。
- **図にできるものは極力図にする**。表やリストに流れがちだが、処理の流れ・構成・対比・階層・状態遷移などは図で表現できないか優先的に検討する。
- **未確定を未確定として残す**。未決・未検証・未対応・保留の項目はそうと分かる形で示す。断定に丸めない。
- 識別子・コード・設定値・パスは等幅で示す。
- HTML の設計指針として `artifact-design` スキルを(`Skill` ツールで)読み込む。

## 引数仕様(`$ARGUMENTS`)

- `<対象>`(必須): ファイルパス、章の指定、トピックなど自由記述。未指定の場合はエラー停止し、ユーザーに確認する(推測で進めない)。
- `--out=<path>`(任意): 保存先パス。未指定時はセッションのスクラッチパッドに書く。スクラッチパッドはセッション終了で失われる可能性があるため、恒久保存したい場合は `--out=` を指定するようユーザーに案内する。
- `--out` はスペース区切り(`--out <path>`)では受け付けない。`=` 区切り(`--out=<path>`)のみとし、それ以外の形式が渡された場合はエラー停止してユーザーに確認する。

## 実行手順

1. `$ARGUMENTS` から `--out=<path>` を分離し、残りを対象の指定として扱う。対象が空の場合はエラー停止してユーザーに確認する。
2. 対象を `Read` / `Grep` / `Glob` で調査する。ファイルパスや章の指定であれば該当箇所を読み、トピック指定であれば関連ファイルを探索する。
3. 元資料から次を漏れなく洗い出す: 専門用語(正式名称のまま)、根拠(ファイルパス・行番号・出典URL・原文引用)、列挙項目(全件)、未確定/未検証/未対応/保留の状態にある項目。
4. `Skill` ツールで `artifact-design` スキルを読み込み、HTML の設計指針(レイアウト・タイポグラフィ・配色・レスポンシブ等)を確認する。スキルが読み込めない環境では、その旨をユーザーに伝えたうえで、本コマンドの原則と手順7の指針(単体 HTML の要件・テーマ対応)に従って続行する。
5. 対象がおおむね1000行を超えるなど大きい場合は、そのまま1ファイルに全件保持する方針から切り替える。章・テーマごとに複数の HTML ファイルに分けるか、対象範囲を絞り込むかをユーザーに確認して決める(内容を間引いて1ファイルに収めることはしない。「内容を変えない・全件保持」の原則は維持したまま、分割か絞り込みで対応する)。
6. 洗い出した内容を、削るのは文章量であって内容ではないという原則のもとで、図・表・リスト等の構造に組み替える設計を作る。要約して情報量を減らすことはしない。図にできるものは極力図にする。
   - 図にすべき類型の例: 処理の流れ・順序(認証フロー、リクエストの経路)、システム間の構成・依存(どのコンポーネントが何を呼ぶか)、対比・分岐(同一プロバイダー vs 別プロバイダー、採用案 vs 不採用案)、階層・包含関係(プロバイダーとチャネル、Pool と Client)、状態遷移。
   - 表のままでよいのは、列が揃った一覧(エンドポイント表、件数表、対応状況の一覧)。
   - 同じ内容を図と表で二重に出さない。
7. HTML を自前で組み立てる。Artifact ラッパーが存在しないため、以下を明示的に書く。
   - `<!DOCTYPE html>` / `<html lang="ja">`(資料の言語に合わせる) / `<head>`(`charset`、viewport、CSS リセット) / `<body>`
   - Web フォントを使う場合は、実在するローカルフォントへのフォールバックスタックを指定する
   - ダークテーマは `prefers-color-scheme` メディアクエリで対応する(`data-theme` 属性は使わない)。`artifact-design` スキルのテーマに関する指示と矛盾する場合は、本コマンドのこの指示を優先する(理由は「動作上の注意」を参照)。
8. 保存先パスを決定する(`--out=` 指定時はそのパス、未指定時はセッションのスクラッチパッド配下)。スクラッチパッドが環境から特定できない場合は、保存先をユーザーに確認する(推測で書き出さない)。`Write` を実行する前に、新規作成・上書きのいずれであっても保存先パスを提示し、ユーザーの承認を得る。承認時にユーザーが別のパスを指定した場合は、そのパスを保存先とする。
9. 承認後に `Write` で書き出す。`--out=` に存在しないディレクトリが指定され `Write` が失敗した場合は、親ディレクトリを作成する手段を持たないため、エラー停止してユーザーに確認する。
10. 保存先パスと、保持した根拠・件数の概況を報告する。

## 出力形式

```
## Visualize 結果

- 対象: <指定内容>
- 保存先: <path>(--out 指定 / スクラッチパッド / 承認時指定)
- 保持した根拠: ファイルパス N件 / 行番号 N件 / 出典URL N件 / 原文引用 N件
- 列挙項目: <項目名> 全N件を保持
- 未確定として残した項目(あれば): ...
- 確認事項(あれば): ...

### 構造化の方針

- 図にしたもの: <対象> → <図の種類>
- 表にしたもの: <対象>
- リストにしたもの: <対象>
```

## 動作上の注意

- Artifact としての公開は行わない。ローカルの HTML ファイルを生成するのみ。
- 用語の言い換え・比喩化、根拠の省略、列挙項目の間引きは行わない。
- `Write` の実行前には必ず保存先パスを提示し、承認を得る(無承認のまま新規作成・上書きしない)。
- `--out=` 未指定時はスクラッチパッドに保存されるため、恒久保存が必要な場合は `--out=` の指定をユーザーに案内する。
- `--out` は `=` 区切りのみを受け付ける。スペース区切りや不明な引数はエラー停止してユーザーに確認する(推測で進めない)。
- `artifact-design` スキルのテーマに関する指示(`data-theme="dark"` / `data-theme="light"` への対応)と本コマンドの指示(`data-theme` 不使用・`prefers-color-scheme` のみ)が矛盾する場合は、本コマンドの指示を優先する。出力は Artifact ではなく単体の HTML ファイルであり、`data-theme` を切り替えるホストが存在しないため。
