# New Issue

`gh issue create` で新規 issue を作成する。

## 目的

会話で挙がった不具合・要望・タスクなどを、内容を正しく反映した issue として素早く記録する。

## 引数仕様(`$ARGUMENTS`)

- タイトル(または題材、省略可): 指定した場合はタイトル、または内容を決めるための題材として使う。省略した場合は会話の文脈から生成する。

## 実行手順

1. `git rev-parse --is-inside-work-tree` でリポジトリ内であることを確認する。
2. タイトルを決定する: `$ARGUMENTS` があればそれをタイトル(または題材)として使い、会話の文脈と合わせて整えたタイトル案を作る。無ければ会話の文脈から生成する。何についての issue か会話からも判断できない場合は、推測で進めずユーザーに確認する。
3. 本文を会話の文脈・依頼内容から作成する(背景・目的、内容、必要に応じて再現手順や受け入れ条件など)。内容の正確性を確認するために必要であれば Read/Grep/Glob で関連ファイルを確認する。
4. タイトルと本文の全文を通常のテキストとしてユーザーに提示し、承認を得る。修正指示があれば反映して再提示し、承認が得られるまで繰り返す(推測で進めず、必ずユーザーの承認を得てから次に進む)。
5. `gh issue create --title "<title>" --body "<body>"` で issue を作成する。

## 出力形式

```
## Issue 作成前の確認

### タイトル
<title>

### 本文
<body>

---

## Issue 作成結果

- URL: <issue URL>
- タイトル: <title>
```

## 動作上の注意

- ラベル・assignee・マイルストーンは付与しない(必要な場合はユーザーが別途 `gh issue edit` 等で設定する)。
- タイトル・本文はユーザーへ全文を提示し、承認を得てから issue を作成する(無承認のまま `gh issue create` を実行しない)。
- issue の内容を推測で補わない。会話の文脈・依頼内容から判断できない場合はユーザーに確認する。
