# 観点別 出力フォーマット（Phase 1 共通）

担当観点の結果を、評価モード別の以下の見出し構成で返す。重大度の判断は `severity-criteria.md` に従う。
凡例: 🔴 Critical: マージ前に必ず修正 / 🟠 High: 修正強く推奨 / 🟡 Medium: 検討推奨 / 🟢 Low・Info: 参考情報

## 良い点の扱い（共通・必須）

`### 良い点` は全モードで**必須**。**指摘より先**に置き、**1〜2行**で簡潔に。無ければ省略せず「特になし」と明記。

## review-branch（差分レビュー・第1パス）

`## [観点名] レビュー（第1パス）` → `### 良い点` → `### 指摘事項` → `### この観点でのカバー範囲`（条件付き）

- 指摘事項: `- 🔴/🟠/🟡/🟢 [ファイル:行] 指摘内容` を並べ、各項目の下に1段下げて `根拠: なぜ問題か` / `提案: 具体的な改善案（コード例があればなお良い）`。0件なら「なし」。
- カバー範囲: **指摘が1件以上ある、または確認できなかった領域・前提がある場合のみ**出す（全て確認済みかつ指摘0件なら節ごと省略）。出す場合は `確認したファイル` と `確認できなかったもの・前提` を各1行。

## review-repo（分類 × 観点スキャン・Phase 1 共通）

`## [分類名] / [観点名] スキャン` → `### 概況`（1〜2段落の総評）→ `### 良い点` → `### 主要発見（上位 $TOP 件、または少数なら全件）` → `### 分布の特徴` → `### 推奨アクション（この観点で）`（短期 / 中期 / 長期）→ `### 制約・前提`（目視推定の箇所、ツール未使用、誤検知要因）

- 主要発見の表: `| 順位 | 対象 | 指標値 | 重大度 | 一言コメント |`（例: `| 1 | path/to/file | 行数 1200 / 変更頻度 45 | 🔴 Critical | ... |`）
- ⚠️ 補助観点（マトリクスの ⚠️）は出力を簡略化: 概況1〜2段落 + 主な発見3件まで（テーブル省略可）。詳細は SKILL.md の「✅（主要）と ⚠️（補助）の運用差」。

## review-slice（スライス評価・Phase 1 共通）

`## [観点名] スライス評価` → `### 概況`（この観点でのスライス全体の総評）→ `### 良い点` → `### 主要発見` → `### スライス特有の論点`（レイヤー越え・コンテキスト越え等）→ `### 制約・前提`（動的解決の影響、追跡できなかった範囲）

- 主要発見の表: `| ファイル | 重大度 | 指摘内容 | 根拠 | 提案 |`
- シンボル起点（`path::symbol`）では各対象に **経路上 / 起点同居 / 依存先** のタグを付す（例: `OrderService.checkout（経路上）` / `order_service.py 他メソッド（起点同居）` / `payment_gateway.py（依存先）`）。起点同居は責務集中の判断材料で、スライス本体（経路上＋依存先）の指摘とは区別する。
